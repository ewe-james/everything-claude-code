# Code Quality Guidelines

## Verify Information

- Verify information before presenting it
- Do not assume or speculate without clear evidence

## Edits and Changes

- Make changes file by file so mistakes are easy to spot
- Provide all edits for a file in a single chunk; no multi-step instructions for the same file
- Do not suggest updates when no real changes are needed
- Do not remove unrelated code or behavior; preserve existing structure

## Communication

- Never use apologies
- Do not give feedback about "understanding" in comments or docs
- Do not suggest whitespace-only changes
- Do not summarize changes made
- Do not ask for confirmation of information already in context

## Scope of Work

- Do not invent changes beyond what was explicitly requested
- Do not ask the user to verify implementations that are already visible in context
- Do not show or discuss the current implementation unless asked

## References

- Always link to real file paths, not placeholders like x.md
